# Risks

Ranked by impact times likelihood. Each has the next step that reduces it. Update the status column when a spike or change lands.

| # | Risk | Impact | Next step | Status |
| --- | --- | --- | --- | --- |
| R1 | Scope: full UTMT parity plus GameMaker-class editors plus Git plus updates in one beta is very large. | Beta slips or ships thin. | Milestones with acceptance checks in roadmap.md; parity matrix tracks every item; G3MLib finished first so the editor never waits on the library. | open |
| R2 | Room editor (layers, tiles, instances, views, GMS1 and GMS2 formats) is the hardest visual editor and UTMT's weakest one. | Main reason users would stay on UTMT. | Spike in M0: render one GMS2 room and one GMS1 room with Avalonia drawing at 60 fps; decide renderer (Avalonia `DrawingContext` vs Skia direct). | open |
| R3 | G3MLib model is not thread-safe and has process-wide statics. | Data corruption when background search or export runs during edits. | Document the thread rule; G3MLib work item 8; tests that run background jobs during edits. | open |
| R4 | Data loss on save or crash. | Users lose game files; trust is gone. | Save pipeline with validation read and backups; recovery copies; fuzz test kill-during-save on all OSes. | open |
| R5 | Dock.Avalonia styling and behaviour may not meet the 2 px rule, persistence or float needs on all OSes. | Rework of the shell. | M0 spike: dock, float, persist, restore, restyle; test on Windows, Linux (X11 and Wayland), macOS. | open |
| R6 | Own updater: integrity and replacement of a running program folder on six RIDs; unsigned builds trigger SmartScreen and Gatekeeper; the program folder may not be writable. | Broken updates, scary warnings, user distrust. | Updater spike (ADR-0005): digest check, interrupted download and extraction, replace and restore, non-writable folder. Signing decided: unsigned beta, documented SmartScreen and Gatekeeper steps (Q7, Q28). | open |
| R7 | UTMT script compatibility: scripts rely on UndertaleModLib API details. | Users keep UTMT for their scripts. | Run the full UTMT bundled script set against G3MLib in CI; list failures per script. | open |
| R8 | Translation quality in 6 languages written in-house from established terminology (Q5). | Inconsistent or awkward UI text. | Glossary per language from G3M, VS Code language packs and GameMaker packs before any string; consistency test against the glossary; known bad source terms excluded (research/gamemaker/gamemaker-terminology.md); native review when someone is available. | open |
| R9 | Memory with large games: decompiled code, textures and undo history held at once. | Slow or crashing on big games. | Lazy decode, LRU caches for textures and decompiled text, undo stores deltas; measure against the budget in architecture.md. | open |
| R10 | New GameMaker versions add chunks or bytecode changes. | Files fail to open. | Unknown chunk passthrough (G3MLib item 2); clear error that names the unsupported version. | open |
| R11 | GML decompile and recompile round trip changes behaviour. | Silent game bugs after an edit. | Only recompile edited entries; compare bytecode of untouched entries on save; G3MLib round-trip tests on a corpus of games. | open |
| R12 | Git without a text project format is useless for data files. | F-GIT-1 cannot work. | G3MLib item 6 (stable project format) before M4. | open |
| R13 | Linux and macOS differences: file dialogs, Wayland, menus, fonts, zip extraction, execute permissions and quarantine flags on extracted files. | Platform bugs late in the cycle. | CI builds all six RIDs from M0; manual smoke test per milestone on each OS; arm64 testers needed (questions.md Q8). | open |
| R14 | Licence: G3MLib is GPL-3.0-only. | Dependencies or assets with incompatible licences cannot ship. | Licence check of every dependency and icon set in CI (THIRD_PARTY_NOTICES). | open |
| R15 | Reverse engineering GameMaker binaries (runner, compiler, IDE) may conflict with the GameMaker EULA. | Legal exposure for the project and its author. | Prefer black-box research: build test projects with the installed GameMaker and read the output with G3MLib. Use disassembly tools only after the owner checks the EULA (questions.md Q16). | open |
| R17 | CI in a designated public repository exposes private G3MStudio code: anything pushed there, plus workflow logs and artifacts, is public while it exists, and forks or caches cannot be recalled. Removing it later does not guarantee it was never seen. | Early leak of the project; traces left in that repo. | Push only build and test workflows that check out G3MStudio from the private repo with a token secret, so the source never lands in the public repo; keep logs minimal; delete runs, artifacts, caches, branches and secrets afterwards and restore the repo's original history. Each push needs the owner's yes. | open |
| R18 | A feature works on one OS or architecture and not on another (native dialogs, file watching, drag and drop, zip extraction, arm64 native libraries). | Second-class platforms; the owner rule is full support everywhere (Q26). | CI-first development on all six targets from M0 (roadmap M0 rule). A feature is blocked on a platform only with documented, extensive CI evidence of impossibility in the platform proof log, a visible UI warning, and a partial implementation tried first. | open |
| R16 | G3MLib 1.1.0 must be final before G3MStudio work starts, but editor work may reveal library needs late. | Either a 1.1.x release mid-project or editor workarounds. | Derive the library work list from the full parity matrix and every planned editor before 1.1.0; prototype the editor-facing APIs in G3MLib tests. | open |
| R19 | Crash reporting (Sentry) leaks paths or game data, or a missing key, bad key, blocked network or exhausted quota breaks the app. | Privacy damage; crashes caused by the reporter. | Scrubbing rules and a test that sends a sample event to a local sink (Q29, Q32); all calls wrapped so a failure is swallowed; builds without keys do nothing; keys only from CI secrets; notice and switch in onboarding before any send. | open |
